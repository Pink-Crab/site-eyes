# site-eyes — agent reference

Synchronous browser-check REST API: POST a URL + what you want back, get
DevTools-grade data from a real headless chromium. Full option reference:
`README.md`. This file is the quick path for an agent driving it.

## Calling it

```
POST   <host>:8080/check          Authorization: Bearer <token>
GET    <host>:8080/health         no auth — {"ok":true,"active":N,"max":3}
GET    <host>:8080/jobs/<jobId>   Bearer — past job, artifacts inlined as JSON
GET    <host>:8080/jobs/<jobId>/<file>   Bearer — raw artifact (png/html/pdf/json)
POST   <host>:8080/a11y           Bearer — axe-core audit {url, timeout?, viewport?}
```

- The token is NEVER in this repo. At runtime the server reads it from
  `SITE_EYES_TOKEN_FILE` (default `/mnt/shared/app/.token`). Get it from the
  deployment, not from any committed file.
- Requests are synchronous — the POST blocks until the capture finishes.
  Budget a 120s client timeout. Worker pool is bounded (`SITE_EYES_WORKERS`,
  default 3); excess callers queue.
- `/health` is honest: HTTP 503 with `ok:false` when the browser is dead —
  check it before a batch, back off when `active == max`.

## Minimal perf-profile payload

```json
{
  "url": "https://example.com",
  "viewport": { "width": 1366, "height": 768 },
  "timeout": 30000,
  "commands": [{ "action": "screenshot", "name": "page", "fullPage": true }],
  "returns": { "summary": true, "webVitals": true, "coverage": true,
               "seo": true, "failures": true, "console": true, "network": true }
}
```

Response: `{ ok, jobId, url, artifactsDir, durationMs, results[], returns{} }`.
`returns` holds only the keys you asked for; each is also persisted to the job
dir as `<key>.json`. `webVitals` = `{ttfb, fcp, lcp, cls, inp}` in ms (`inp`
usually null — no interaction). Binary artifacts (screenshots, PDFs) are never
base64d into JSON — fetch them via `/jobs/<jobId>/<file>`.

## Rules of thumb

1. Single runs vary ±30% — run ≥3 passes and average when comparing anything.
2. `returns.html` is heavy — request it only when you need the rendered DOM.
3. `evaluate` runs arbitrary JS in the page context; never put secrets in it.
4. Failures self-heal: a dead browser exits the process and systemd relaunches
   it (queue is lost — re-submit). Retry once on connection errors.
5. Anything the named `returns` keys don't cover is one raw `cdp` call away:
   `"cdp": [{ "method": "Accessibility.getFullAXTree" }]`.

## Layout

| File | Role |
|---|---|
| `server.js` | Fastify API, auth, worker pool, job persistence |
| `executor.js` | runs the `commands` sequence on the page |
| `collect.js` | gathers the `returns` data (CDP + DOM) |
| `site-eyes.service` | systemd unit (paths assume `/mnt/shared/app`) |

Operate: `sudo systemctl {status,restart} site-eyes` on the host.
